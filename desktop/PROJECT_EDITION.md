The user approved the current working version and requested removal of obsolete local releases on 29 October 2026. Only the current bundle/installer is retained; historical release paths are reference records. See [workspace maintenance](../docs/WORKSPACE_MAINTENANCE.md) for current paths and rebuild commands.

The shared JD brief now distinguishes implementation requirements, knowledge, qualifications and recruiter logistics. Experience parsing recognizes YOE; the higher explicit overall duration wins, while specialties stay separate. These changes retain the existing fictional generation and the 11-call base workflow; quality findings are review prompts, not an ATS score.

# Resume Optimizer Project Edition 1.3.0

## Phase 1 profile quality

New generations write six substantial professional-summary bullets after project
repairs. The first starts with the JD target role and a numeric experience total:
the higher explicit overall total from the source/JD, otherwise 9+ years.
Specialty durations are stored separately and included in the summary opening.
Skills use bold, relevant categories and retain implementation concepts/practices.
Each project includes Target Role and Contribution metadata.

Generation seeds and cache identities are fresh per Generate action; retries share
that identity. Certifications are selected from JD-relevant families rather than
a mandatory fixed trio. New schema-6 documents omit calendar dates from all body
sections, including education; existing saved documents retain their date policy.
Full fictional generation remains enabled. The fixed free-RAM startup gate is
removed; the 4 GiB runtime cap remains. Model, context and hosting are unchanged. Phase 2 is deferred until the user accepts the output quality.

The pipeline uses at most 21 normal section calls, two single-shot project quality
calls and three shared retries (26 possible); a hard guard remains at 27.
See [Phase 1 verification](PHASE1_RESULTS.md) for current results. Notes below
also describe earlier editions; their measurements are historical.

Separate Windows 11 x64 application. Install `dist/ResumeOptimizerProjectsSetup.exe`.
Its shortcut is **Resume Optimizer Project Edition**. The existing Resume
Optimizer Desktop app and installers are preserved.

## Full-stack generation

Python/React full-stack JDs receive separate application engineering, GenAI
integration (only when requested) and production delivery contributions. Checks
require React implementation, database/API behavior, tests, reviewed AI-assisted
coding and operational evidence rather than a skills-list mention. The report
re-reads edited experience claims and separates overall/specialty requirements.
See [full-stack verification](FULL_STACK_RESULTS.md).

## Resume format

One editable **Relevant Project Experience** section contains three employer /
designation blocks, each with one complete project and six substantial implementation bullets. Employer names remain visible. Project
clients use the exact text `Confidential client`. Dates remain absent from employment
and projects; identity, contact and education remain preserved. Other typography
and field formatting stay consistent with the existing exports.

Client labels are forced before project generation, and known client aliases
are masked in descriptions. Edited Client fields are masked again at preview /
export. Employer headings, project titles, institutions and technology vendors
are retained. This is resume formatting, not a general document anonymizer.

The complete fictional mode is retained. Evidence checks run locally without
per-skill model calls. Initial generation uses 19 calls, with at most three
validation retries and two single-shot quality repairs (24 normally; hard cap 27 submissions,
excluding bounded transport retries). Quality depends on the small CPU model;
review generated claims and report gaps before using an export.

## Isolation and memory

Data: `%LOCALAPPDATA%/ResumeOptimizerProjectEdition`. This includes drafts, logs,
caches and artifacts. Install directory and registry key are separate from the
existing app. No drafts are automatically imported or migrated between editions.
Both GUIs can open together; there is no minimum-free-RAM startup gate.
Each edition owns its loopback model server and never attaches to the other.
Inference uses one 4,096-token slot, at most four CPU threads and 768 output
tokens per call; the 4 GiB application memory safeguard remains enabled.
Independent installations each include their offline model/runtime assets.

Uninstall keeps saved data. Updating this edition replaces only this edition's
installation. Close this edition before installing/upgrading; the old app may
remain open. No Python, Docker, n8n, subscription or account is needed to run it.

## Developer build

Run `desktop/build_projects.ps1` in PowerShell on Windows x64. Assets are pinned
and checksum-verified by the existing preparation script. The first developer
build can require internet; target installation/use includes all assets offline.
The installer is unsigned. Clean disconnected Windows and actual 8 GB laptop
qualification remain release gates when that hardware is unavailable.

retrieval/embedding boilerplate and Additional Capabilities fragment injection
are removed. Compact project rendering uses overview, metadata and six bullets.

Two quality calls share one budget, do not trigger nested validation retries,
and cannot discard the completed resume. Replacements that increase the local
